# STORY-00-02-01 — API host + module interface

**Status:** `dev_done` (local tests green; say UAT pass to close)  
**Epic / feature:** EPIC-00 / FEAT-00-02  
**Branch:** `story/STORY-00-02-01-api-host`

## What

`Healingram.Api` boots, registers the eight modules through `IAppModule`, and returns JSON from health and meta.

## Why

Later stories need a single process that is already alive on your laptop. The website will talk to the gateway; the gateway will talk to this host.

## Acceptance

- `GET /api/health` returns `{ status, version, time }` with `status = ok`
- `GET /api/meta` returns `{ environment, service, version }`
- Modules register via `IAppModule` (eight names + schemas)
- Each module exposes `GET /api/{module}/ready`
- Unit/host tests cover the payload shape (no Postgres required)

## Out of scope

- Gateway as the website’s `/api` door (STORY-00-02-02)
- Catalog needs/places from inventory (EPIC-01)
- Login

## Local how-to-test

```text
dotnet test backend/Healingram.slnx
dotnet run --project backend/src/Healingram.Api
# GET http://localhost:5080/api/health
# GET http://localhost:5080/api/meta
# GET http://localhost:5080/api/catalog/ready
```

Schema apply on startup still wants Docker Postgres when you run the real host. Tests set `Schema:ApplyOnStartup=false`.
