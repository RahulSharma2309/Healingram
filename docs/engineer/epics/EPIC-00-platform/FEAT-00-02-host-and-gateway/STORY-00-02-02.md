## What

The public `/api` door on your laptop is the **gateway** (`http://localhost:5000`). It forwards health, meta, OpenAPI, and module `/ready` to `Healingram.Api` (`:5080`). It stamps `X-Correlation-Id`. It does not write business data.

## Why

The website will only ever call `VITE_API_BASE_URL` (local: `http://localhost:5000`). It must not talk to `:5080` or to Postgres.

## Acceptance

- Gateway exposes `/api/health`, `/api/meta`, `/api/docs` (or OpenAPI equivalent)
- Those routes return the same JSON the API already returns
- Response includes `X-Correlation-Id` (new id if the client sent none; same id if it did)
- Unit tests for correlation-id create/forward; no business writes in the gateway project
- Website env can be `VITE_API_BASE_URL=http://localhost:5000` (no frontend rewrite required in this story)

## Out of scope

- Auth
- Catalog places API
- Docker one-command stack (STORY-00-05-01)

## Local how-to-test

```text
dotnet run --project backend/src/Healingram.Api
dotnet run --project backend/src/Healingram.Gateway
# GET http://localhost:5000/api/health
# GET http://localhost:5000/api/meta
# Response header X-Correlation-Id is present
```
