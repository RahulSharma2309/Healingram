# Flow — Availability request (customer)

**Who:** a guest who is ready to ask the retreat “can we come?”

## Happy path

1. Check Availability validates the stay. First missing field gets focus.
2. Logged-in guests see their name/email/phone prefilled. Others type them. Notes are optional and treated as sensitive.
3. Review shows the stay and price and says **No payment yet**.
4. Submit creates one request (a second tap does not create a second one).
5. They see “Availability request received”, the request id, View My Request, Explore more.

## While they wait

My Request shows what they submitted (it does not change if rates change later), any alternative the retreat proposed, and the next honest action.

## If the retreat cannot honour it

Three doors, no dead end: try different dates, see similar retreats, talk to an expert.

## Alternative

Requested vs proposed are compared side by side. Accept freezes the new snapshot and moves them toward payment. Decline does not pretend the original dates are still held.
